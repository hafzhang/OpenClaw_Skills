# 教程大纲模板

本模板用于规划教程的整体结构和内容。

## 1. 基本信息

| 字段 | 说明 |
|------|------|
| **教程 ID** | tutorial-XXX（遵循现有编号规范） |
| **标题** | 简洁、描述性强、包含关键技术词 |
| **Slug** | kebab-case 格式，URL 友好 |
| **难度级别** | beginner / intermediate / advanced |
| **预计阅读时间** | 基于字数估算（200-300 字/分钟） |
| **分类** | quick-start / productivity / development / content / creative |
| **作者** | 作者名称或昵称 |

## 2. 目标受众

明确教程的目标受众群体：

- **技能水平**：（例如：熟悉命令行，有 Python 基础）
- **角色背景**：（例如：后端开发者、DevOps 工程师）
- **使用场景**：（例如：需要自动化日常任务）

## 3. 前置条件

列出学习本教程的前置知识：

- [ ] OpenClaw 已安装并配置
- [ ] 具备 XXX 基础知识
- [ ] 已完成前置教程（如有）
- [ ] 拥有 XXX 账号/权限

## 4. 学习目标

使用 SMART 原则定义学习目标（具体、可衡量、可达成、相关、有时限）：

完成本教程后，学习者将能够：

1. **理解**：[概念/原理] 的工作原理
2. **掌握**：[技能/操作] 的使用方法
3. **实现**：[具体功能/目标] 的完整流程
4. **解决**：[实际问题/场景] 的常见问题

### 学习目标示例（Beginner - Python 自动化入门）

完成本教程后，你将能够：

1. **理解** Python 自动化脚本的基本结构和执行流程
2. **掌握** OpenClaw Python 技能的安装和配置方法
3. **实现** 文件操作、数据处理等常见自动化任务
4. **解决** 日常开发中的重复性工作问题

### 学习目标示例（Intermediate - Rust 系统编程）

完成本教程后，你将能够：

1. **理解** Rust 的所有权系统和内存安全模型
2. **掌握** 并发编程的基本模式和最佳实践
3. **实现** 高性能的系统级应用程序
4. **解决** 常见的并发和性能问题

### 学习目标示例（Advanced - 分布式系统设计）

完成本教程后，你将能够：

1. **理解** 分布式系统的核心理论和设计原则
2. **掌握** CAP 定理在实际系统中的应用
3. **设计** 高可用、可扩展的分布式架构
4. **解决** 分布式事务、一致性等复杂问题

## 5. 章节结构

### 标准章节（所有教程）

1. **标题和简介**（1-2 段落）
   - 简要说明教程内容
   - 说明学习价值

2. **前置条件**（列表形式）
   - 必需的知识、工具、权限

3. **学习目标**（4-6 个要点）
   - 使用"理解、掌握、实现、解决"等动词开头

4. **背景知识**（可选，Beginner 教程建议包含）
   - 相关概念介绍
   - 技术背景说明

5. **实战步骤**（核心内容）
   - 按步骤组织
   - 每步包含说明 + 代码示例
   - 预期结果说明

6. **配置示例**（如适用）
   - 完整配置文件
   - 参数说明表格

7. **常见问题（FAQ）**（至少 3 个）
   - 常见错误和解决方案
   - 最佳实践建议

8. **进阶内容**（可选，Intermediate/Advanced 建议）
   - 高级技巧
   - 性能优化
   - 扩展方向

9. **相关资源**
   - 官方文档
   - 相关教程
   - 相关技能（仓库必须可访问）

10. **总结**
    - 回顾要点
    - 下一步学习建议

### 章节长度指南（按字数）

| 难度 | 总字数 | 章节数 | 每章平均 | 代码示例 |
|------|--------|--------|----------|----------|
| Beginner | 2000+ | 5-6 | 400-500 | 5+ |
| Intermediate | 2500+ | 6-8 | 400-500 | 6+ |
| Advanced | 3000+ | 8-10 | 400-500 | 8+ |

### 实战步骤章节模板

每个实战步骤应包含：

#### 步骤 X：[步骤标题]

**目的**：简述这个步骤的目的

**操作**：
1. 第一步操作
2. 第二步操作

**代码示例**：
```bash
# 示例命令
command with options
```

**说明**：解释代码的作用和关键参数

**预期结果**：
```
# 预期的输出或状态变化
```

**注意事项**：
- 可能遇到的问题
- 替代方案（如有）

## 6. 实战案例规划

每个教程应包含实际可运行的案例：

### Beginner 教程
- 至少 **2 个** 简单实战案例
- 案例 1：基础功能演示
- 案例 2：常见场景应用

### Intermediate 教程
- 至少 **3 个** 中等复杂度案例
- 案例 1：标准流程
- 案例 2：异常处理
- 案例 3：优化改进

### Advanced 教程
- 至少 **4 个** 复杂案例
- 案例 1：完整系统
- 案例 2：性能调优
- 案例 3：故障排查
- 案例 4：最佳实践

- [ ] 代码可独立运行（或清楚说明依赖）

- [ ] 遵循语言最佳实践
- [ ] 包含错误处理（如适用）
- [ ] 格式规范、缩进统一

## 9. FAQ 规划

预先规划常见问题：

1. **安装/配置问题**
   - Q: 常见安装错误
   - A: 解决方案

2. **使用问题**
   - Q: 常见使用错误
   - A: 排查步骤

3. **最佳实践**
   - Q: 如何优化/改进
   - A: 建议方案

4. **故障排查**
   - Q: 遇到错误 X
   - A: 诊断和解决

发布前完成以下检查：

- [ ] 标题清晰，包含关键词

- [ ] 每个代码示例可运行
- [ ] 所有链接有效且可访问
- [ ] 相关技能的 GitHub 仓库存在
- [ ] FAQ 覆盖常见问题
- [ ] Markdown 格式正确
- [ ] 代码块指定语言
- [ ] 阅读时间估算准确
- [ ] 语法拼写正确
- [ ] 技术术语准确

## 11. 时间估算

估算各部分写作时间：

| 部分 | 预计时间 | 备注 |
|------|----------|------|
| 大纲设计 | 30-60 分钟 | 明确结构和目标 |
| 背景知识 | 30-45 分钟 | 查阅资料，确保准确 |
| 实战步骤 | 2-3 小时 | 核心内容，需要验证 |
| 代码示例 | 1-2 小时 | 测试验证 |
| FAQ 整理 | 30-45 分钟 | 基于常见问题 |
| 审查修改 | 30-60 分钟 | 质量检查 |
| **总计** | **5-8 小时** | 按难度调整 |
