# 教程创作流程文档

本文档说明了从零开始创建教程的完整流程，包括规划、编写、审核和发布的各个阶段。

---

## 流程概览

```
规划阶段 → 编写阶段 → 审核阶段 → 发布阶段
   ↓          ↓          ↓          ↓
大纲设计   内容编写    质量检查    集成发布
主题选择   代码验证    技术评审    测试验证
目标定义   FAQ 编写    内容评审    文档更新
```

---

## 第一阶段：规划（Planning）

### 1.1 主题选择

**步骤**：
1. 查看教程主题列表（docs/tutorial-topics-phase3.md）
2. 选择待编写主题
3. 确认主题没有被重复编写

**检查项**：
- [ ] 主题在计划列表中
- [ ] 主题 ID 未被使用
- [ ] 主题与现有教程不重复

**输出**：教程主题确定

### 1.2 大纲设计

**步骤**：
1. 复制 `tutorial-outline.md` 模板
2. 填写基本信息
3. 定义学习目标
4. 规划章节结构
5. 列出代码示例清单

**检查项**：
- [ ] 使用大纲模板
- [ ] 学习目标符合 SMART 原则
- [ ] 章节结构完整
- [ ] 实战案例已规划

**输出**：`tutorial-XXX-outline.md`

### 1.3 相关技能验证

**步骤**：
1. 列出教程涉及的所有技能
2. 验证每个技能的 GitHub 仓库
3. 确认仓库返回 HTTP 200
4. 确认仓库内容相关

**检查项**：
- [ ] 所有技能仓库存在
- [ ] 所有仓库可访问
- [ ] 技能 ID 正确

**输出**：相关技能验证清单

---

## 第二阶段：编写（Writing）

### 2.1 准备工作

**步骤**：
1. 创建工作分支：`git checkout -b tutorial/tutorial-XXX`
2. 创建教程文件：`tutorial-XXX-draft.md`
3. 设置本地开发环境：`npm run dev`

**检查项**：
- [ ] 分支创建成功
- [ ] 开发环境运行正常

### 2.2 编写教程内容

**步骤**：
1. 按照大纲编写各章节
2. 添加代码示例
3. 编写实战案例
4. 编写 FAQ

**检查项**：
- [ ] 所有章节完整
- [ ] 代码示例数量达标
- [ ] 实战案例数量达标
- [ ] FAQ 数量达标

**参考**：
- 代码示例规范：`code-example-standards.md`
- FAQ 模板：`faq-template.md`

### 2.3 代码验证

**步骤**：
1. 运行所有命令示例
2. 测试所有代码片段
3. 验证配置文件
4. 确认输出示例

**检查项**：
- [ ] 所有命令可执行
- [ ] 所有代码可运行
- [ ] 输出示例准确
- [ ] 没有硬编码敏感信息

### 2.4 链接验证

**步骤**：
1. 检查所有外部链接
2. 检查所有内部链接
3. 验证技能仓库
4. 验证教程链接

**检查项**：
- [ ] 外部链接可访问
- [ ] 内部链接正确
- [ ] 技能仓库返回 200
- [ ] 教程链接存在

**工具**：
```bash
# 检查链接工具（可选）
npm install -g markdown-link-check
markdown-link-check tutorial-XXX-draft.md
```

### 2.5 格式化内容

**步骤**：
1. 检查 Markdown 格式
2. 统一代码风格
3. 规范标题层级
4. 确保缩进一致

**检查项**：
- [ ] Markdown 格式正确
- [ ] 代码块指定语言
- [ ] 标题层级规范
- [ ] 缩进统一

---

## 第三阶段：审核（Review）

### 3.1 自我检查

**步骤**：
1. 使用质量检查清单：`tutorial-quality-checklist.md`
2. 逐项检查并打勾
3. 记录发现的问题
4. 修复所有问题

**检查项**：
- [ ] 完成质量检查清单
- [ ] 所有问题已修复
- [ ] 自查通过

### 3.2 技术评审

**评审内容**：
- 技术准确性
- 代码质量
- 最佳实践
- 安全性

**评审者**：技术团队成员

**检查项**：
- [ ] 技术内容准确
- [ ] 代码符合规范
- [ ] 遵循最佳实践
- [ ] 没有安全隐患

### 3.3 内容评审

**评审内容**：
- 语言表达
- 逻辑结构
- 学习体验
- 实用性

**评审者**：内容编辑或产品

**检查项**：
- [ ] 语言准确流畅
- [ ] 逻辑清晰连贯
- [ ] 适合目标受众
- [ ] 实际应用价值

### 3.4 评审反馈处理

**步骤**：
1. 收集评审意见
2. 按优先级分类
3. 修改教程内容
4. 重新提交评审

**检查项**：
- [ ] 所有意见已处理
- [ ] 修改已验证
- [ ] 评审通过

---

## 第四阶段：发布（Publishing）

### 4.1 准备元数据

**步骤**：
1. 准备教程 JSON 元数据
2. 估算阅读时间（字数 / 250）
3. 选择合适的分类和标签
4. 设置难度级别

**JSON 模板**：
```json
{
  "id": "tutorial-XXX",
  "title": "教程标题",
  "slug": "tutorial-slug",
  "description": "简短描述",
  "content": "Markdown 内容（转义后）",
  "category": "development",
  "tags": ["标签1", "标签2", "标签3"],
  "difficulty": "beginner",
  "readTime": 15,
  "author": "作者名",
  "relatedSkills": ["skill-XXX"],
  "stats": {
    "viewCount": 0
  },
  "createdAt": "2026-02-05T00:00:00Z",
  "featured": false
}
```

**内容转义**：
```bash
# 使用 Node.js 转义 Markdown
node -e "console.log(JSON.stringify(require('fs').readFileSync('tutorial.md', 'utf8')))"
```

### 4.2 更新数据文件

**步骤**：
1. 打开 `src/data/tutorials.json`
2. 添加新教程元数据
3. 验证 JSON 格式
4. 保存文件

**检查项**：
- [ ] JSON 格式有效
- [ ] ID 唯一
- [ ] slug 唯一
- [ ] 所有必需字段完整

### 4.3 构建验证

**步骤**：
1. 运行类型检查：`npm run type-check`（如可用）
2. 运行构建：`npm run build`
3. 检查构建输出
4. 验证生成的页面

**检查项**：
- [ ] 类型检查通过
- [ ] 构建成功无错误
- [ ] 教程在列表页显示
- [ ] 详情页正常渲染

### 4.4 本地测试

**步骤**：
1. 启动开发服务器：`npm run dev`
2. 访问教程列表页
3. 访问教程详情页
4. 测试所有功能

**检查项**：
- [ ] 列表页显示教程
- [ ] 详情页渲染正常
- [ ] 代码高亮正常
- [ ] 链接跳转正常

### 4.5 提交代码

**步骤**：
1. 提交更改：`git add . && git commit -m "feat: US-XXX - 教程标题"`
2. 推送到远程：`git push origin tutorial/tutorial-XXX`
3. 创建 Pull Request
4. 等待 CI 检查通过

**检查项**：
- [ ] 代码已提交
- [ ] PR 已创建
- [ ] CI 检查通过

### 4.6 代码审查

**步骤**：
1. 请求代码审查
2. 回应审查意见
3. 修改后更新 PR
4. 获得批准

**检查项**：
- [ ] 至少一人审查
- [ ] 所有意见已处理
- [ ] 获得批准

### 4.7 合并发布

**步骤**：
1. 合并 PR 到主分支
2. 部署到生产环境
3. 验证线上版本
4. 更新文档

**检查项**：
- [ ] PR 已合并
- [ ] 部署成功
- [ ] 线上验证通过

## 第五阶段：发布后（Post-Publish）

### 5.1 文档更新

**更新文件**：
- `progress.txt`：添加完成记录
- `prd.json`：更新用户故事状态
- `README.md`：更新教程数量（如需要）

### 5.2 监控反馈

**监控指标**：
- 页面浏览量（stats.viewCount）
- 用户反馈
- 搜索使用
- 相关技能安装量

### 5.3 持续改进

**改进方向**：
- 根据用户反馈更新内容
- 添加更多 FAQ
- 更新代码示例
- 修正错误

## 常见问题

### Q: 可以跳过大纲设计直接编写吗？

A: 不推荐。大纲设计能确保教程结构清晰，内容完整，避免后期大幅修改。

### Q: 代码示例必须全部测试吗？

A: 是的，所有代码示例必须经过验证，确保用户能按教程成功运行。

### Q: 如何估算阅读时间？

A: 使用字数除以 250（每分钟阅读字数），再加上代码示例理解时间（每个示例加 1-2 分钟）。

### Q: 技能仓库验证失败怎么办？

A: 寻找替代技能或联系管理员更新技能库。不要链接到不存在的仓库。

### Q: 教程发布后可以修改吗？

A: 可以。创建新的分支进行修改，经过同样的流程后合并。
